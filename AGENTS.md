# Agent Instructions

## GitHub release notes

When you create or update a GitHub release, describe the version's changes **in the release body itself** — do not point to `WhatsNew.md` with a link only.

- Extract the `# FindRomCover <version> — What's New` section from the repository's `WhatsNew.md` (everything up to the next `# FindRomCover` heading, dropping the trailing `---`) and use it as the release body.
- The extracted section already contains the download list; keep it in the body.
- Only fall back to a changelog link when the section for the tagged version cannot be found (for example when the tag predates the changelog).
- `.github/workflows/release.yml` implements this rule automatically when a `release_*` tag is pushed. Manual releases (`gh release create` / `gh release edit`) must follow the same rule.

## Documentation

- `docs/` feeds both the GitHub Pages site (MkDocs Material, navigation in `mkdocs.yml`) and the GitHub wiki (generated by `scripts/Sync-Wiki.ps1`, sidebar from the same script). Keep both side menus in sync when adding or renaming pages.
- Release documentation lives in `WhatsNew.md`, `docs/release-notes.md`, and `README.md`; update all three for every release.
